SYNTHESIS · DOT PRODUCTS · MATRICES

One row, one dot product, one output.

How can a company compare two project proposals? First, it records ratings and chooses which criteria matter most. Then a matrix product turns that information into one comparable score per proposal.

SUBJECTS USEDDot productsMatrix multiplication

Start with the company's assessment

A company has limited funding or staff time. It needs to decide which of two projects to prioritize. Its team examines each proposal and gives it a rating for:

  • Impact: the expected benefit.
  • Feasibility: how practical it is to carry out.

For this example, ratings use a scale from 1 (low) to 5 (high). The team's assessment gives these numbers:

Project ratings: impact and feasibility
ProposalImpactFeasibility
Proposal A42
Proposal B34

These are project-specific ratings, based on the team's observations; the calculation will not verify whether the ratings are accurate.

Separately, the company decides how much each criterion matters. It gives impact weight 3 and feasibility weight 4. These are shared weights: both proposals will be evaluated with the same values. Feasibility matters slightly more in this example.

Shared criterion weights
CriterionWeight
Impact3
Feasibility4

A weight says how much a criterion matters in the total. A weighted sum multiplies each rating by its shared criterion weight, then adds the products. Teams use this kind of scoring to compare options, for example when prioritizing projects or selecting vendors. It helps organize a decision; it does not make the decision for them.

Now encode the two tables as mathematical objects. Matrix R stores project ratings, one proposal per row. The vector w stores the shared criterion weights in the same column order: impact, then feasibility.

RATINGS AND CRITERION WEIGHTSR=[4234],w=[34]
READ IT ALOUD

R contains the ratings: proposal A has impact four and feasibility two; proposal B has impact three and feasibility four. The weight vector w assigns weight three to impact and four to feasibility.

Each row of R belongs to one proposal: the first row is proposal A, the second is proposal B. The columns are the criteria, in order: impact first, feasibility second. The vector w lists the corresponding criterion weights in that same order. We write the two resulting proposal scores as a column vector s.

Important: both proposals use the same shared weight vector w. Only the ratings row changes. We do not adjust the weights separately for A and B; using one common scoring rule is what makes their scores comparable.

SHAPES(2×2)(2×1)=2×1
READ IT ALOUD

R has two rows and two columns; w has two rows and one column. The shared size of two fits, so the result has two rows and one column: one score for each proposal row.

This is a matrix times a column vector. It follows the same shape rule as the matrix multiplication lesson: the columns of the first matrix must match the rows of the second. Here, each rating row pairs with the two criterion weights to produce that proposal's score.

Proposal A: one row, one dot product

Proposal A's first row in R is (4,2): impact is rated 4 and feasibility is rated 2. Match that row with the criterion-weight vector (3,4). Multiply matching entries and add, just as in the dot-product lesson.

PROPOSAL A SCOREsA=4×3+2×4=12+8=20
READ IT ALOUD

Proposal A's score is its impact rating, four, times the impact weight, three, plus its feasibility rating, two, times the feasibility weight, four. That is twelve plus eight, or twenty.

The proposal's rating row and the column of criterion weights make a dot product: pair impact rating 4 with impact weight 3, and feasibility rating 2 with feasibility weight 4, then add. This one dot product produces one number—the score for proposal A.

Proposal B: repeat with its ratings

Proposal B's row in R is (3,4): impact is rated 3 and feasibility is rated 4. The criterion weights stay the same, so pair this row with (3,4) again:

PROPOSAL B SCOREsB=3×3+4×4=9+16=25
READ IT ALOUD

Proposal B's score is its impact rating, three, times the impact weight, three, plus its feasibility rating, four, times the feasibility weight, four. That is nine plus sixteen, or twenty-five.

Put the two scalar scores into a column, in the same order as the proposal rows:

MATRIX PRODUCTs=Rw=[2025]
READ IT ALOUD

The score vector s is R multiplied by w. Proposal A scores twenty and proposal B scores twenty-five.

Each row of R produces one output: the number of proposal rows tells us how many scores we get. Under these chosen ratings and weights, proposal B leads proposal A by five points. This is exactly the row-by-column rule for matrix multiplication, with a single column on the right.

What does the score tell us—and not tell us?

For this particular scoring model, 25 is higher than 20, so proposal B ranks above proposal A: its stronger feasibility rating more than offsets its lower impact rating when feasibility has the larger weight. The scores are weighted points, not percentages or ratings out of 5; with both criteria rated 5, the maximum would be 5×3+5×4=35 weighted points. They are not probabilities, and they do not prove that proposal B is objectively better. A different rating scale or different weights could change the ranking; the numbers make the team's assumptions visible, but do not choose those assumptions for it.

THE CONNECTION

Why use a matrix product here?

The project-prioritization example has two proposals and two criteria. Each row of the ratings matrix describes one proposal; the weight vector describes how important each criterion is. A row-by-column dot product turns each proposal's two ratings into one weighted score, and matrix multiplication repeats that calculation for all proposals at once.

This pattern is useful whenever several options are evaluated with the same criteria and weights. The score helps compare options under the stated model; it does not replace judgment about whether the ratings and weights make sense. For a fuller matrix-by-matrix example, revisit matrix multiplication. For the matching-and-adding operation itself, revisit vectors and dot products.
