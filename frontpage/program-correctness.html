PROGRAM CORRECTNESS · LOOP INVARIANTS

Why does this loop give the right answer?

Earlier lessons translated sums into loops and counted how much work those loops do. This page asks a different question: how do we know a loop actually computes the sum it claims to compute—for every allowed input, not just the examples we tried?

State the promise before tracing the loop.

In the summation lesson, a loop stood in for a mathematical sum. In counting work, we asked how often loops run. Neither a small test nor a work count proves that the loop gives the right answer; that is the purpose of this lesson.

We want to add the whole numbers from 1 through an input n. A precondition says which inputs this claim covers: here n must be a nonnegative integer (0, 1, 2, and so on). A postcondition says what must be true when the loop finishes: total must contain that sum.

GOAL AT THE ENDtotal=∑k=1nk
READ IT ALOUD

When the loop ends, total equals the sum of the integers from one through n.

The letter k in the sum only labels the terms being added. The code calls its changing counter i; consistently renaming the summation index would not change the sum.

What stays true before and after every pass?

The loop invariant describes the work already finished. i counts how many numbers have been added; total is their sum:

INVARIANTtotal=∑k=1ik
READ IT ALOUD

Total equals the sum of the integers from one through i—the numbers added so far.

Initially i = 0 and total = 0: no numbers have been added. A sum with no terms is an empty sum, equal to zero. If n = 0, the loop never runs; i == n and the answer is already zero.

At i = n = 4, i < n is false. The loop ends without increasing i past n; the total already includes the final value 4.

Why this works for every allowed n

  1. Start: i = 0, total = 0. No numbers have been added, so the invariant holds.
  2. Keep it true: assume total sums the numbers through i. When i < n, increase i by one and add that new value. Now total again sums the numbers through the new i. This start-and-repeat reasoning is the same idea as induction.
  3. Finish: each pass increases i by one while it is less than n. Starting at 0 with nonnegative integer n, it reaches i == n and stops. The invariant then says total sums exactly the numbers through n—the postcondition.

The first assert checks the precondition for this run. At the end, assert i == n checks the boundary, and sum(range(1, n + 1)) independently checks this run’s result. Assertions can catch mistakes for tested inputs; they do not prove the result for every allowed n. The start, keep, and finish reasoning does that.

Where this leads

The same start, maintain, finish pattern helps explain search algorithms and other loops. More complex proofs need careful definitions of their assumptions and goals.
